ბრაუზერში მუშაობს, მაგრამ ინტერნეტი არ სჭირდება: ყველა ფაილი (შრიფტები, ბიბლიოთეკები) პროექტშივეა.

> **ვერსია: ყველა ეტაპი (1–6).** ინგრედიენტები, მიღება, რეცეპტები, წარმოება, მზა პროდუქცია, გატანა,
> ინვენტარიზაცია, რეპორტები (Excel/PDF), მთავარი გვერდი გრაფიკებით, ცვლილებების ჟურნალი, სარეზერვო ასლები.

### Windows
ორჯერ დააწკაპუნეთ ფაილზე **`start.bat`**.

```bash

```
თუ Ubuntu/Debian-ზე გამოჩნდა შეცდომა ვირტუალურ გარემოზე: `sudo apt install python3-venv`

ცარიელ ბაზაზე მთავარი გვერდი სთავაზობს ღილაკს **„სადემონსტრაციო მონაცემების ჩატვირთვა“** (იგივე ღილაკია **პარამეტრებშიც**).

## როგორ მუშაობს

### ყოველდღიური სამუშაო — 3 ნაბიჯი
1. **მიღება** → „ახალი მიღება“: დაასკანერეთ შტრიხკოდები. რაოდენობის, ფასის ან თანხის შემდეგ Enter-ით კურსორი ისევ ძიებაზე ბრუნდება შემდეგი სკანირებისთვის. ბოლოს დააჭირეთ „შენახვა და დადასტურება“-ს.
2. **წარმოება** → „ახალი წარმოება“: აირჩიეთ პროდუქტი და რაოდენობა. პროგრამა აჩვენებს, რა ჩამოიწერება და რა აკლია. დააჭირეთ „გამოშვება და ჩამოწერა“-ს.
3. **გატანა** → „ახალი გატანა“: დაასკანერეთ ან მოძებნეთ პროდუქცია. ნაშთზე მეტის გატანა შეუძლებელია.

### საბუთის სტატუსები
| სტატუსი | ნაშთზე გავლენა | რა შეიძლება |
|---|---|---|
| **დრაფტი** | არა | რედაქტირება, დადასტურება, წაშლა |
| **დადასტურებული** | დიახ | რედაქტირება (ნაშთები ავტომატურად გადაითვლება), გაუქმება (სტორნო) |
| **გაუქმებული** | არა (მოძრაობები ამოღებულია) | მხოლოდ ნახვა, ისტორიისთვის რჩება |

რედაქტირება და გაუქმება ყოველთვის **ერთ ტრანზაქციაში** სრულდება: ან ყველაფერი ჩაიწერება, ან არაფერი.
მაგალითად, მიღებას ვერ შეამცირებთ ან ვერ გააუქმებთ, თუ მისი ინგრედიენტი უკვე დაიხარჯა წარმოებაში. ამ შემთხვევაში პროგრამა გეტყვით, რომელ ინგრედიენტს რამდენი აკლია და რომელ თარიღზე.
ნაშთი მოწმდება **დღეების მიხედვით**: წინა თარიღით შეყვანილი ხარჯი ვერ „გაუსწრებს“ მიღებას.

### რეცეპტები და თვითღირებულება
- რეცეპტში მითითებულია: **გამოსავალი** (1 პარტია = მაგ. 10 ცალი), ინგრედიენტები ნებისმიერი თავსებადი ერთეულით და **დანაკარგი %**. დანაკარგი ხარჯს ემატება: 1 კგ + 5% = 1,05 კგ.
- რეცეპტის ვერსია, რომელიც წარმოებაში უკვე გამოიყენეს, **იკეტება**. შესაცვლელად დააჭირეთ „ახალი ვერსია“-ს და შემდეგ „აქტიურად გახდომა“-ს. ძველი ვერსიები ისტორიაში რჩება.
- წარმოების საბუთი ინახავს **ფაქტობრივად ჩამოწერილ** რაოდენობებს და იმ დღის ფასებს. ამიტომ რეცეპტის ან ფასის შემდგომი ცვლილება ძველ საბუთებს არ ცვლის.
- ფასის მეთოდი (პარამეტრებში): **საშუალო შეწონილი** (ნაგულისხმევი) ან **ბოლო ფასი**.
- ინგრედიენტის ნაკლებობისას (პარამეტრებში): **დაბლოკვა** (ნაგულისხმევი) ან **გაფრთხილებით დაშვება**.

**აღდგენა:**
1. დახურეთ პროგრამა.
2. შეინახეთ მიმდინარე `data/app.db` სხვა ადგილას (ყოველი შემთხვევისთვის).
3. სასურველი ფაილი `backups/app-....db` გადააკოპირეთ `data/` საქაღალდეში და დაარქვით `app.db`.
4. თუ `data/`-ში არის ფაილები `app.db-wal` და `app.db-shm`, წაშალეთ ისინი.
5. გაუშვით პროგრამა.

მთელი პროგრამის სხვა კომპიუტერზე გადასატანად საკმარისია `data/app.db`-ის გადაკოპირება.

---

## პარამეტრები (გარემოს ცვლადები)

| ცვლადი | ნაგულისხმევი | აღწერა |
|---|---|---|
| `APP_PORT` | `8000` | პორტი |
| `APP_DATA_DIR` | `data/` | ბაზის საქაღალდე |
| `APP_BACKUP_DIR` | `backups/` | ასლების საქაღალდე |
| `APP_BACKUP_KEEP` | `30` | რამდენი ასლი შეინახოს |
| `APP_DATABASE_URL` | SQLite `data/app.db` | მაგ. PostgreSQL-ზე გადასვლისთვის |

პროგრამა ხელმისაწვდომია მხოლოდ იმავე კომპიუტერიდან (`127.0.0.1`).

## დეველოპერისთვის

### სტრუქტურა
```
app/
  models/       ბაზის ცხრილები (SQLAlchemy)
  services/     ბიზნეს-ლოგიკა: UI-სგან დამოუკიდებელი, აქ იწერება ტესტები
  web/routes/   გვერდები (FastAPI)
  templates/    HTML (Jinja2 + HTMX + Bootstrap)
  i18n/ka.py    ინტერფეისის ყველა ტექსტი
  formatting.py ქართული ფორმატები (თანხა, რაოდენობა, თარიღი)
  db_types.py   ზუსტი Decimal ტიპები ბაზისთვის
alembic/        ბაზის მიგრაციები
tests/          pytest ტესტები
```

### პრინციპები
- **ტექსტები** მხოლოდ `app/i18n/ka.py`-შია. სერვისები აბრუნებენ შეცდომის გასაღებს და არა ტექსტს.
- **რიცხვები:** მხოლოდ `Decimal`. float-ის გადაცემა შეცდომას იწვევს. ბაზაში ინახება მასშტაბირებულ მთელ რიცხვად (BIGINT), ამიტომ SQLite-ზეც ზუსტია და PostgreSQL-ზეც უცვლელად მუშაობს.
- **ტრანზაქციები:** სერვისები `commit`-ს არ აკეთებენ. ამას გამომძახებელი აკეთებს, რომ რთული ოპერაციები (მაგ. წარმოება) სრულად შესრულდეს ან საერთოდ არ შესრულდეს.
- **ავტორიზაცია:** `users` ცხრილი და `get_current_user` უკვე არსებობს. ჟურნალი იწერს მომხმარებელს, ამიტომ შესვლის ფორმის დამატებისას სხვა კოდის შეცვლა არ დასჭირდება.
